# UX 全面 Review 与优化计划（2026-09-05）

> 范围：takoapi.com 全部面向用户的页面（首页 / 市集 / 详情 / 技能 / 榜单 / 安装 / 博客 / 场景 / 登录注册 / 开发者控制台 / 提交流程 / 后台）+ 全站文案（`messages/en.json` 618 键，抽样 zh / ja / de）+ 邮件模板。
> 方法：逐文件走读 `src/app/[locale]/**`、`src/components/**`；线上实测（curl 计时、HTML 结构、公开 API 返回）；对照 `docs/agent-marketplace/` 已拍板的产品决策（D1–D8）。
> 配套技术审查见 [08-tech-review-2026-09-05.md](08-tech-review-2026-09-05.md)。

---

## 0. 一句话结论

产品定位已经从「OpenClaw skills 市集」转向「One API to access all agents」，**但用户看到的仍是两个产品缝在一起**：导航、搜索、首页版块、登录文案、邮件都在两种叙事之间来回切换；而对已拍板的「开发者优先」（D4）这条主线，从首页到详情页到控制台，**缺一条清晰的「看到 → 拿 key → 30 秒调通」路径**。此外有一批影响信任的细节（首页精选中挂着探活为 down 的 agent、详情页仍写着「网关 Phase 2 才上线」、Skill 详情页纯客户端渲染），修复成本低但优先级高。

线上基线（2026-09-05 实测）：

| 指标 | 数值 |
|---|---|
| 目录规模（首页 hero 展示） | 52 个 HOSTED agent · 1,558 个开源项目 · 5,385 个 skill |
| 首页 HTML | 271 KB，68 个 `<script>` |
| 首页 TTFB | 冷 1.5 s / 热 0.8–0.9 s |
| `/agents` TTFB | 热 0.7–1.1 s |
| 404 页 | Next.js 默认「404: This page could not be found.」，无品牌无导航 |
| Skill 详情页 SSR | 无（HTML 中无 `<h1>`，内容全靠客户端 fetch） |

## 1. 信息架构与产品叙事

### 1.1 双产品叙事互相打架 🔴

| 触点 | 现状 | 证据 |
|---|---|---|
| 顶部导航 | `Agents · Skills · Trending · Publish`：Trending 只有 skills，Publish 只发 agent，skill 提交入口藏在个人页 | `src/components/layout/Header.tsx:51-119` |
| 两个搜索框去向不同 | Header 搜索 → `/agents?q=`；首页大搜索框 → `/skills?q=`（占位文案还是 "Search skills by name…"） | `Header.tsx:31`，`src/components/ui/HomeSearch.tsx:16` |
| 首页结构 | hero 讲 agents，往下 8 个版块里 4 个是 skills（Official skill 横幅 / Must-Have / Categories / Latest Skills） | `src/app/[locale]/page.tsx` |
| 页脚 | "Built for the OpenClaw community"；资源区只链 awesome-openclaw-skills 与 clawskills.sh | `messages/en.json` `Footer.copyright` |
| 登录页副标题 | "Access your skills dashboard" | `Auth.signInSubtitle` |
| 欢迎邮件 | 标题区「All in One OpenClaw Skills Marketplace」「5,000+ OpenClaw skills」「clawhub install takoapi」 | `src/lib/email.ts:37,41,53` |
| KOL 外联邮件 | "the OpenClaw skills marketplace with 5,000+ skills" | `src/lib/email.ts:155` |
| 用户菜单 | "My Skills"（个人页只列 skill 提交，**看不到自己提交的 agent**） | `Header.tsx:81`，`src/app/[locale]/profile/page.tsx` 只调 `/api/user/skills` |

**影响**：新访客读完首页不知道 TakoAPI 到底是什么；publisher 提交 agent 后无处查看审核状态（见 §5.2）。

**建议**：
1. 明确主线 = **Agents（HOSTED + PROJECT）**，Skills 降级为「coding-agent skills」子品类（与 D2 一致）。导航改为 `Agents · Projects · Skills · Blog · Install`，主 CTA 固定为「Get API key」。
2. 全站**一个搜索**：默认搜 agents，带作用域切换（Agents / Projects / Skills）；两处搜索框走同一组件与同一路由。
3. 清一遍所有「OpenClaw skills marketplace」口径：页脚、登录副标题、欢迎邮件、外联邮件、README 项目结构段。
4. 个人页改成「My Listings」：agents + skills 两个 tab。

### 1.2 术语冲突 🟠

- **"Agents"** 同时指：可调用的 HOSTED agent、开源 PROJECT、以及 skills 筛选里的「coding agent 类型」（`Skills.agentAll` = "All agents" → Claude Code / Cursor…）。
- **"Skills"** 同时指：OpenClaw skill 条目，和 A2A AgentCard 里的 `skills[]`（agent 卡片上的 "5 skills"、详情页的 "Skills (5)"）。
- **"Projects" / "self-host" / "open-source"** 三个标签混用在同一张卡上。

**建议**：定一张术语表并落到 `messages/en.json`：`Agent`（可调用）、`Project`（开源，仅发现）、`Capability`（AgentCard skills[]）、`Skill`（coding-agent skill）、`Coding agent`（Claude Code 等）。

## 3. 发现与浏览

### 3.1 `/agents` 市集页 🟠

- **筛选墙**：Kind（3）+ Scenario（17）+ Protocol（3）+ Pricing（4）+ Category（N）+ Sort（5）全部平铺成 chip，一屏 40+ 个可点元素（`agents/page.tsx:188-268`）。没有「当前筛选摘要 / 一键清除」，多选一次要滚回顶部。
- 搜索表单是原生 `<form action="/agents">`（`:171`），在 `/zh/agents` 搜索会跳回英文 `/agents`。
- 排序 `Popular` 按 `likesCount`（几乎全 0），等于随机；默认 `latest` 对 1,600 条目录不如 `stars` / `calls` 有意义。
- 分页只有 Prev / Next，没有页码与总页数跳转；`PAGE_SIZE=24` 但 URL 参数 `page` 非法时静默回 1。
- 卡片不显示 health / 最近更新时间 / 是否经验证，HOSTED 与 PROJECT 两种卡信息密度差异大。

**建议**：筛选改为左侧栏（桌面）/ 抽屉（移动），顶部只留搜索 + Kind 切换 + 排序；显示 active filter chips；默认排序按 kind 自适应（HOSTED→calls，PROJECT→stars）；卡片加 health 点与「updated 3d ago」。

### 3.2 `/skills` 列表页 🔴

- 整页 `"use client"`，首屏是骨架屏再 fetch（`skills/page.tsx:1,42-63`）；对 5,385 个 skill 的入口页，搜索引擎拿到的是空壳。
- 筛选/排序/页码只存 React state，**不写回 URL**：不能分享、刷新即丢、浏览器后退无效（`:32-35,121`）。
- 分类是 `<button>` 而非链接，无法中键/新标签打开。
- 从 header 搜索进入的是 `/agents`，从首页搜索进入的是 `/skills`，用户不会知道区别。

### 3.3 `/trending` 🟡

- 与 `/skills?sort=downloads` 是同一数据的另一套皮（同样 CSR）；表头 "Downloads" 是 clawskills.sh 抓取值而非本站数据（PR #52 已把文案改掉）。
- 建议合并进 `/skills` 的排序，或做成真正的「7 日增量」榜单。

### 3.4 `/scenarios` 🟡

- 17 个场景分布极不均：Agent Frameworks 1,124 / Coding 417 / Research 366 vs Sales 4 / VC 4 / Product Design 5。四五个条目的场景落地页对用户和 SEO 都是 thin content。
- 建议：≤10 条的场景不在首页磁贴出现、落地页加「相关场景」；分类器关键词按分布调整（08 §6.3）。

## 5. 转化漏斗（开发者 & publisher）

### 5.1 开发者：看到 → 拿 key → 调通 🔴

1. 登录：无邮箱验证、无忘记密码、注册后自动登录固定跳首页；所有需登录的页面（dashboard / profile / submit / submit-agent / bookmarks）都是「请先登录」占位 + 跳转，登录后不回到原页。
2. Dashboard（`dashboard/page.tsx`）：`status === "loading"` 时 `return null` 整页白屏（`:92`）；创建 key 默认命名 "Gateway key" 不可改；用量只有 15 条最近调用的表格，没有时间范围与图表；quickstart 仍只有 curl。
3. 没有 `/docs`：API 说明只在 README 与 SKILL.md，控制台里没有错误码 / 限流 / 计费规则说明。
4. 没有「在浏览器里试一次」：从拿 key 到第一次成功调用，用户必须离开网站。
5. 充值面板文案「Credits are funded by the platform for now — self-serve PayPal top-up is coming soon」与 PayPal 是否已配置耦合，用户不知道自己有多少额度可用、超了会怎样。

**建议**：登录全链路带 `callbackUrl`；dashboard 首屏加 onboarding checklist（创建 key → 复制示例 → 首次调用成功 ✅）；加「Try an agent」内嵌调用面板（用当前 key 调 `/v1/chat/completions`）；建 `/docs` 静态页（quickstart / auth / endpoints / errors / billing）。

### 5.2 Publisher：提交 → 审核 → 上架 🔴

- `/submit-agent` 提交成功后只显示「pending review」一屏，之后**没有任何地方能看到审核状态**（个人页只有 skills），也没有邮件通知（审核通过/拒绝都不发）。
- `reviewNote` 通过公开 API 暴露（08 §2.6），却不在 publisher 自己的界面展示。
- 提交表单没有预览、没有 AgentCard 校验的即时反馈（要提交后才知道 card 拉不下来）。

**建议**：个人页加 My Agents（状态 + 审核备注）；审核结果邮件；表单加「Validate card」按钮（复用 `fetchAgentCard`）实时显示解析出的 name / skills。

### Phase U3 · 打磨（持续）

- 可访问性审计（对比度、焦点态、表单错误 `aria-describedby`、skip link）；目标 WCAG 2.1 AA。
- 母语校对（zh → ja → de → es → fr），每语种四页。
- Cookie consent / 或切换到无 cookie 统计。
- 组件层抽取（Button / Input / Card / Badge / EmptyState / Dialog），后台 `prompt/confirm` 全部替换。
- 可选：深色模式。
