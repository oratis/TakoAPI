## 3. 🟡 性能与扩展性

### 3.1 零缓存 + 全站 `force-dynamic`

首页 / `/agents` / 详情 / 场景 / badge 页全部 `export const dynamic = "force-dynamic"`，每次请求 5–9 个 Prisma 查询打 db-f1-micro；所有 HTML 与 JSON 都是 `Cache-Control: private, no-store`。热 TTFB 0.7–1.1 s 全部花在 DB 往返。目录数据（agents / skills / categories / counts）本质上分钟级新鲜度即可。

方案（按仓库 Next 16.2.1 文档 `node_modules/next/dist/docs/01-app/02-guides/caching-without-cache-components.md` 与 `01-getting-started/08-caching.md`）：
1. 短期：`unstable_cache` 包住只读查询（首页各版块、`/agents` 列表、categories、scenario counts、registry），`revalidate: 60–300`，打 tag（`agents`、`skills`、`categories`）；admin 写路径与 cron 结束时 `revalidateTag`。
2. 公开 GET API 加 `Cache-Control: public, s-maxage=60, stale-while-revalidate=300`；在 Cloud Run 前挂 Cloud CDN（或 Cloudflare）让 sitemap / registry / badge / 列表页命中边缘。
3. 中期：启用 `cacheComponents: true` + `"use cache"` / `cacheLife`，把首页做成静态 shell + Suspense 流式；登录态相关组件（Header 的 session）已是 client 组件，不阻塞。
4. 目标：首页热 TTFB < 150 ms，DB QPS 下降一个量级。

### 3.2 搜索无索引、无排序权重

`name/description contains + mode: insensitive` → `ILIKE '%q%'` 全表扫描；`Skill.name` 的 btree 索引对 contains 无效；`Agent.scenarios` 数组 `has` 无 GIN 索引（migration 007 注释里明说「先不加」）；搜索结果只按 `likesCount desc`（全 0）。
建议：`pg_trgm` GIN（`name`, `description`）+ `tsvector` 生成列（name A 权重、description B、AgentSkillDef.name C）做 `ts_rank` 排序；`scenarios` 加 GIN；MCP `search_agents` 与网页共用同一 search service。

### 3.3 数据库与连接

db-f1-micro（1 shared vCPU / 0.6 GB）+ Cloud Run `maxScale=20 × containerConcurrency=80` + Prisma 默认连接池（每实例 `num_cpus*2+1`）→ 峰值可超 Cloud SQL 连接上限；无 PgBouncer；`docs/agent-marketplace/03 §9` 早已列为网关前置。建议：升到 db-custom-1-3840 或 db-g1-small；`DATABASE_URL?connection_limit=5&pool_timeout=10`；评估 Cloud SQL 内置连接池 / PgBouncer sidecar。

### 3.4 每请求写放大

- 网关每次调用 `lastUsedAt` 更新（`apikey.ts:39`）→ 改为 60 s 内最多写一次（内存节流）或批量。
- `RequestLog` 无限增长（PR #52 加 90 天保留）；`Invocation` 长期需要按月分区或归档。
- 限流表每次请求 `INSERT … ON CONFLICT` 一次往返（可接受，但 60 s 窗口下 `RateLimitBucket` 清理靠随机触发）。

### 3.5 前端体积

首页 271 KB HTML / 68 个 script 标签，主要是 RSC payload 与 15 语种路由；`Header` 是 client 组件并把 `next-auth/react` 与 `lucide-react` 拉进首屏。建议：图标按需（已是 ESM tree-shake，确认 bundle）；Header 拆成 server shell + 小的 client 岛（session 菜单 / 搜索）；开启 `experimental.optimizePackageImports`。

## 5. 🟢 中期架构建议

1. **网关数据面**：透传完整 A2A（message parts / task / contextId），返回 task 结构；per-agent 断路器（连续失败 → 快速 503，而不是每次等 30 s 超时）；`healthStatus=down` 的 agent 直接快速失败；上游超时按 agent 可配；A2A 流式加 `X-Accel-Buffering: no`。
